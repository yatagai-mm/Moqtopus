Moqtopus connects your application to a MOQT relay. Use a subscriber session to
receive objects, or a publisher session to register tracks and send objects to
subscribers. Both APIs are in the `moq` namespace and use the same transport
configuration.

## Start here

- [Getting started](./getting-started/): build the library and link your C++ application.
- [Subscriber](./subscriber/): connect, subscribe, receive objects, and update a subscription.
- [Publisher](./publisher/): register a track and publish over streams or datagrams.

## Session model

1. Configure the relay endpoint with `MsQuicClientConfig`.
2. Call `connect(...).get()` to create the session and start the transport.
3. Call `ready().get()` to wait for the MOQT SETUP exchange.
4. Subscribe to tracks or register tracks and publish objects.
5. Stop subscriptions or finish tracks, then close the session.

`connect()` does **not** wait for MOQT readiness. A returned session can still be
connecting; wait for `ready()` before subscribing or publishing.

## Scope

The implementation targets MOQT draft-18 (`moqt-18`). This documentation describes
the public headers and behavior in this checkout, rather than every feature of
the protocol. There is no public FETCH request API. The publisher sends live
objects and does not replay a stored history to new subscribers.

Received payloads are borrowed views that expire when `on_object()` returns.
Read [Types & ownership](./types/) before passing received data to another thread.

## Future failures

Call `.get()` on returned futures to observe failures. Connection startup,
readiness, subscription, and update errors are reported through futures.
A peer REQUEST_ERROR becomes `moq::RequestRejected`, which derives from
`std::runtime_error`.

```cpp
#include <moq/subscriber_session.h>
#include <exception>
#include <iostream>
#include <memory>
#include <utility>

void subscribe_with_errors(moq::MoqSubscriberSession& session,
                           moq::SubscribeRequest request,
                           std::shared_ptr<moq::ObjectHandler> handler) {
  try {
    auto handle = session.subscribe(std::move(request), std::move(handler)).get();
    std::cout << "Subscribed: " << handle.request_id() << '\n';
    // Keep the session alive; destroying handle does not unsubscribe.
  } catch (const moq::RequestRejected& error) {
    std::cerr << "Rejected: " << static_cast<uint64_t>(error.code())
              << " reason=" << error.reason()
              << " retry interval=" << error.retry_interval() << '\n';
  } catch (const std::exception& error) {
    std::cerr << "Local or transport failure: " << error.what() << '\n';
  }
}
```

`RequestRejected::code()`, `retry_interval()`, and `reason()` expose the decoded
peer values. The library does not automatically retry requests. `what()` includes
a formatted error code and reason.

`ReceiveError` contains `uint64_t code` and `std::string message`. Check the
message as well as the code: some callback failures use a generic code rather
than a specific wire error. Do not interpret every callback code as a
`RequestErrorCode`.

## Session state

`SessionStateSnapshot` is returned by either session's `state()` method.

| Field | Meaning |
| --- | --- |
| `phase` | `Init`, `SetupInProgress`, `Ready`, `Closing`, or `Closed`. |
| `local_setup_sent` | Whether local SETUP has been sent. |
| `peer_setup_received` | Whether peer SETUP has been received. |
| `negotiated_version` | Optional string; the implementation records the configured ALPN once ready. |
| `active_subscriptions` | Current number of subscriptions held by the session. |
| `close_reason` | Optional `SessionCloseReason` with a `SessionCloseErrorCode code` and `std::string message`. |

Normal setup progresses from `Init` to `SetupInProgress` to `Ready`. Shutdown
enters `Closing`, then `Closed`; failure may start shutdown before readiness.
`close()` initiates shutdown and does not return a peer acknowledgment.

## Subscription state

`SubscriptionStateSnapshot` contains `phase`, `request_id`, optional
`track_alias`, and `size_t inflight_updates`. Obtain it from a handle's `state()`.

| Phase | Meaning |
| --- | --- |
| `Pending` | Waiting for the first subscription response. |
| `Established` | SUBSCRIBE_OK received; updates are allowed. |
| `UpdateFailed` | A REQUEST_UPDATE was rejected. Inspect the failed update future. |
| `Terminated` | Subscription ended or no live state is available. |

The current implementation requires `Established` for further updates. After
`UpdateFailed`, stop the subscription and create a new one if needed.

## Error-code families

All four enums below use `uint64_t`. Codes overlap between families; retain the
context in which you received each code.

### SessionCloseErrorCode

| Name | Value |
| --- | --- |
| `NoError` | `0x0` |
| `InternalError` | `0x1` |
| `Unauthorized` | `0x2` |
| `ProtocolViolation` | `0x3` |
| `InvalidRequestId` | `0x4` |
| `DuplicateTrackAlias` | `0x5` |
